## 준비

- 반례 작성: PM의 자아를 가지고 현재 문제에서 개발자가 놓칠 수 있는 사항을 반례로 작성한다.

## 구현

- 시나리오 작성: 존재하지 않는 코드로 문제를 표현하고, IDE의 생성/리팩토링 기능을 활용하여 뼈대를 만든다.
- 입출력 형식: 입력 문자열에서 어떤 형식의 정보를 추출해야 하는가? 화면 출력에 필요한 형식의 정보는 무엇인가?
- 핵심 기능: 주석으로 고수준 문맥을 유지하고, 확신이 없는 부분부터 테스트한다.

```
요구사항

indent 최대 2
함수 길이 15 라인
3항 연산자, else, switch/case 사용 불가
파일 수정과 패키지 이동 자유

camp.nextstep.edu.missionutils.Randoms.pickNumberInList()
camp.nextstep.edu.missionutils.Console.readLine()

public enum Coin 활용: 필드(인스턴스 변수)인 `amount`의 접근 제어자 private을 변경할 수 없다.
```

- 자판기는 상태를 가지기 때문에 테스트가 어렵다. 자판기의 핵심은 계산이다.
   - 따라서, 별도의 연산기 클래스를 작성하여 별도의 상태 없이 테스트 가능하도록 만든다.
